## Verification is STRUCTURAL, and the order was fail-closed

An exit code alone is not proof — that is `#178`'s own lesson, and this plan shipped the fix
for it. So:

- the tracker create was verified by a **returned issue URL** (`.../issues/193`), then by
  `gh issue view 193` reporting `number 193`, `state OPEN`, the **verbatim** title with no
  doubled `plan-` prefix, and a 2561-byte body containing the full plan id (SC19) and the epic
  id;
- **every one of the six `include` comments was verified present before ANY close ran.** The
  close loop is gated on that check and halts with nothing closed if a single comment is
  unverified. Commenting and closing are separable, and a close on an issue whose attribution
  never landed is precisely the `fail` state `_verify_row` exists to catch;
- all eleven end states were re-read from GitHub afterwards.

## Routing

**The tracker create was routed through `/yf-beads-upstream`** —
`upstream.py push --issues yf-mol-m3e --apply`, dry-run first — never a hand-run
`gh issue create`. That is the mandated path and its rationale applies exactly here: the
skill's push is gh-direct and records the mapping with `bd update --external-ref`, so the
tracker is an **ordinary mapped bead**, visible to `upstream.py closable`. Confirmed:
`bd show yf-mol-m3e` carries `external_ref: https://github.com/dixson3/yoshiko-flow/issues/193`.
A raw create would have recorded no ref and left an issue nothing can map back to a bead —
the #117/#131 defect, and why five earlier trackers went stale and were closed by hand.

**The comments and closes were not routed, because there is no verb to route them to, and
that is a documented gap rather than a shortcut.** `upstream.py`'s verbs are `enumerate |
mappings | granularity | config | followons | closable | reconcile | push | hoist | land |
unhoist`. `push` maps a **bead** to an issue; `#178` and its siblings are pre-existing upstream
issues with no bead mapping, so there is nothing for it to create or edit. The skill's own
SKILL.md says so in two places: Push step §6 names `gh issue comment` as the path for content
that is not bead-synced, and §9 (`closable`) states its contract as *"emits the `gh issue
close <N>` commands and stops. Read them, then run the ones you agree with."*

The safety invariant's stated reason for the routing mandate is that a raw create **records no
`external_ref`**. That reason is specific to creates, and the one create here was routed. A
`gh issue comment` on an already-existing, never-a-bead issue has no mapping to record.

**SC17 is satisfied on its second branch, as the criterion anticipates.** Exit 0 alone is
insufficient — only `fail` halts, so `inconclusive` also exits 0 — and the criterion therefore
requires either `pass`, or `inconclusive` **with the inconclusive rows being exactly the one
`tracker` row**. That is the measured state. `tracker` returns `inconclusive` **by
construction** (REQ-CLI-018): the coarse tracker is closed by the land-the-plane sweep, not by
reconciliation, so it carries no end-state contract in either direction.
