plan-061 adopted this issue's principle — *"a step with no exit code is not a step"* — as a
binding design constraint, and it shows up in three places in what shipped:

- **`REQ-YF-DOC-010`** requires the README contract to be enforced by a **runnable check**
  rather than an on-edit prose obligation. The four `DRIFT-CHECK.md` README edges had existed
  for months with no firing surface; 18 of 20 skills failed one of them silently.
- **`REQ-YF-DOC-015`** pins the `--min-skills` floor to exit **2**, not 1. A floor tripping at 1
  is byte-identical to a real contract failure, so a gate reading "exits non-zero" would be
  satisfied by a checker that enumerated nothing — a step whose exit code cannot distinguish the
  two states is, for that distinction, not a step.
- **`REQ-YF-DOC-016`** makes the JSON **verdict** the gate predicate rather than the exit code,
  because an uncaught exception and a genuine FAIL both exit 1.

**Deliberately not addressed:** M9's remediation-edge scope. plan-061's remit was the README and
