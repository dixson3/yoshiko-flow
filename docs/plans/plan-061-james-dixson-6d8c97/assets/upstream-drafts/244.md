## Root cause, which the issue title does not name

`DRIFT-CHECK.md` declares the four README edges, but **nothing ran them**.
`CHANGE-VALIDATION.md:6` excludes `yf-drift-check` as a *"prose/LLM trigger, not a runnable
command"*, so the only firing surface was an on-edit prose obligation — and #273 measured that
prose naming an obligation is skipped where prose naming a command is followed.

## What changed

`scripts/checks/check_skill_readme_contract.py` now implements the **mechanical subset** of the
four edges (layout, prereqs, usage, README existence) and is wired into `CHANGE-VALIDATION.md`'s
FAST and FULL tiers, with `skills/*/SKILL.md` and `skills/*/README.md` trigger globs. The
contract itself is pinned in `SPEC.md` §3.11 (`REQ-YF-DOC-001..018`) rather than in the script,
so the exclusion set and the fence form are reviewable.

All 34 findings are now zero across 20 skills. Two failure modes your issue could not have seen:

- **`yf-okf-hygiene` had no README at all** (it shipped after this issue was filed). That is an
  *absence*, not a mismatch, and `skill-readme` being a `required` node enforced nothing —
  `required` only means reference-validity checks apply *if the artifact is present*. The checker
  now reports `missing-readme` as its own class.
- **Two more READMEs taught unprefixed invocations** (`/beads-init`, `/markdown-lint`) beyond the
  `/beads-upstream` and `/incubator` already known — invisible to a manual survey for exactly the
  reason your counts went stale.
