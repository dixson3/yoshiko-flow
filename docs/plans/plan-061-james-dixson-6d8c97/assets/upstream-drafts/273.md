Consumed as **design input** by plan-061 (`plan-061-james-dixson-6d8c97`, tracked in
#315), which is the strongest kind of
citation this issue can get: its law is the reason that plan chose the fix it did.

`DRIFT-CHECK.md` declared four README edges. `CHANGE-VALIDATION.md:6` excluded `yf-drift-check`
as a *"prose/LLM trigger, not a runnable command"*, so the only firing surface those edges ever
had was an **on-edit obligation** — and this issue's finding is precisely that prose naming an
obligation is skipped where prose naming a command is followed.

The measured consequence: **18 of 20 skills** failed `e-readme-layout`, and nothing noticed. #244
reported "16/19"; by the time plan-061 re-derived the figures they had already moved to 18/20,
inside a single plan-cycle.

So plan-061 did not merely repair the READMEs. It built
`scripts/checks/check_skill_readme_contract.py` **first**, proved it red against the
pre-backfill tree, repaired against it, and wired it into `CHANGE-VALIDATION.md`'s FAST and FULL
tiers — converting the obligation into a command. `SPEC.md` `REQ-YF-DOC-010` states the law
directly:

> the contract shall be enforced by a runnable check … not by an on-edit prose obligation.

**Not closed by this plan.** plan-061's own Upstream Issues table records this row as design
input with no resolver — one instance being converted does not discharge a general law, and
closing it on that basis would be exactly the kind of unproven claim the law warns about.
