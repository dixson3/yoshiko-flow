## Finding: EXP-001 native gate-step roles and compatible classifier identity
### Approach Tested
- Read installed formula, resolver and fidelity comparator; fetched gastownhall/beads v1.3.1 source and v1.1.0 cook source. Captured exact upstream commit refs and content digests in versions.json and tag/commit receipts.
- Ran the identical unmodified installed plan-execute formula under installed Homebrew bd 1.3.1 and a downloaded, checksum-verified native bd 1.1.0 release. Each had a separate disposable git repository and embedded Dolt store, outside YF/PIM. Native older-tool pour, NOT a retyped newer graph.
- Every experimental subprocess used a strict environment allowlist, sandbox HOME and scratch cwd. No ambient BEADS_*, GIT_*, XDG_*, PIM_* or resolver variables were retained. No real tracker store was opened.
- Captured native pour/id_mapping, list --all --include-gates --limit 0, individual show records, gate show, resolution, closure, premature-close and wrong-target-resolution probes. Raw stdout/stderr and argv/exit receipts are preserved under current/ and historical/.
- Parsed scratch bd status JSON before pours: both valid, no error key, empty initialized stores. Canonical yf preflight was attempted additionally: initial restricted PATH lacked uv; corrected PATH reaches rule_missing because sandbox HOME intentionally has no installed BEADS_INIT.md. No repair/install was attempted. This is NOT claimed as a green yf preflight; native DB usability was measured directly.
### Result
- **measured:** v1.3.1 tag resolves to commit c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c; v1.1.0 to 8e4e59d39f3459a43cf21a3236a13eca4dd874f7. Installed version says `bd version 1.3.1 (Homebrew)`; downloaded binary says `bd version 1.1.0 (8e4e59d39)`. Homebrew source equivalence was not independently rebuilt.
- **measured:** BOTH native pours create exactly three nodes: root molecule, Begin wrapper, human gate. Both outputs identify them using exact keys `plan-execute`, `plan-execute.start-gate`, `plan-execute.gate-start-gate` in id_mapping. All three IDs are independently allocated; dotted-ID derivation is invalid.
- **measured:** 1.3.1 wrapper is `issue_type=gate` with no await_type. 1.1.0 wrapper is `issue_type=task` with no await_type. The real gate is `issue_type=gate`, `await_type=human`, description `Async gate for step start-gate` in BOTH. Both wrapper and gate have parent-child to the same molecule; wrapper has exactly one blocks edge to the human gate. Native root type is molecule, not epic.
- **measured:** list dependencies use `{issue_id, depends_on_id, type}`; show dependencies embed the target issue and use `{id, issue_type, dependency_type}`. Show wrapper dependency_count=2 includes containment, while list dependency_count=1 excludes containment. A shared classifier must normalize edge formats, NOT compare these counts.
- **measured:** neither fresh graph contains source_formula, source_location, plan ID, fingerprint or role metadata. Upstream processStepToIssue assigns source fields to the cooked proto, but cloneSubgraphInto does not copy them into poured nodes. Its copied fields include metadata, but the installed formula provides no such metadata. Therefore source_formula/source_location are NOT available as a native persisted role key for this repair.
- **measured:** v1.1.0 stepTypeToIssueType has an enum switch without `gate`, defaulting unknown types to task. v1.3.1 normalizes/preserves non-empty declared types. createGateIssue independently creates the human gate from `[steps.gate]` in current source. This matches both measured pours.
- **measured:** resolving the REAL gate closes it but leaves the wrapper open in BOTH versions. A subsequent ordinary bd close of the wrapper succeeds. Closing the wrapper before resolving the real gate is refused in BOTH versions, with `cannot close blocked issue ... (use --force to override)`; no force was used.
- **measured, safety-critical:** on 1.3.1, `bd gate resolve <WRAPPER>` succeeds and closes the wrapper while the actual human gate stays OPEN. On 1.1.0 that same wrong-target operation fails because wrapper is a task. Native gate resolve directly calls store.CloseIssue after type validation; unlike ordinary close, this command did not protect the blocks edge. Wrapper closed != human consent resolved.
- **measured:** installed resolver only admits task wrappers and falls back to a generic Gate:-titled child when it cannot get gate dependencies; installed fidelity counts every gate-typed descendant. Those algorithms disagree with the native 1.3.1 role split. Fidelity currently has title-only scaffold filtering for tasks as well; do not copy that strategy to gate exclusions.
- **inferred:** a graph-only structural match cannot authenticate native provenance. An arbitrary hand-created lookalike can copy every persisted field and edge. Corroboration: native JSON has no distinct persisted origin token, and clone source omits source fields. Persisted raw pour mapping bound to plan/root identity is the strongest AVAILABLE stable role evidence; its JSON is not cryptographically authenticated merely by existing.
### Implications for Plan
- **inferred, corroborated by both native pours and pinned source:** count the actual human gate once; do not count a proven Begin wrapper as an additional declared gate regardless of its task/gate issue type. One shared classifier should give resolver and fidelity the same role pair and explicit missing/ambiguous/inconclusive outcome.
- **inferred, corroborated by wrong-target probe and gate.go:** resolver must resolve only the mapped/validated actual human gate; then re-read its closed status before ordinary wrapper closure. Never use gate resolve on a gate-typed wrapper and never treat closed wrapper as consent. A preclosed wrapper with open actual gate remains unresolved.
- **inferred:** fail-closed historical support cannot require absent source fields. Prefer the existing immutable pour receipt (including all three exact mapping keys), tied to the expected plan/root and approved fingerprint through existing plan evidence. If no trusted role receipt exists, classify inconclusive rather than certify arbitrary Begin-shaped graphs. Parent must inspect actual retained PIM mapping to establish whether this stronger path is available; this investigation did not touch its live graph.
- **inferred:** rejecting a missing mapping is a compatibility policy choice requiring explicit SPEC wording, not a claim native bd persisted provenance. Future role metadata may help, but is not necessary to invent for this bounded repair if saved mapping is already available. Do not silently retrofit provenance into PIM's graph.
### Recommendations
1. Define normalized node/edge input with strict errors for missing target reads, duplicate IDs, malformed/conflicting types, conflicting parent declarations and incomplete snapshots. Normalize list `type` versus show `dependency_type` deliberately; containment is not a blocks edge.
2. Bind classifier to explicit expected root and native mapping keys; require three distinct IDs, actual membership under that root, wrapper in {task,gate} without await semantics, actual gate type gate with await_type human, and an actual wrapper-to-gate blocks edge. Validate uniqueness; reject a second competing pair or role assignment. Titles/descriptions may corroborate but must not establish identity. Status must not affect structural role recognition.
3. Separate structural classification from consent state, and keep every non-wrapper gate visible to gate fidelity. Never exclude all Begin-titled gates or all no-await gates. Preserve missing/extra/duplicate gate checks, issue/epic and dependency checks, approved-plan fingerprint/root checks and fail-closed inconclusive handling. Note current fidelity is count-based for gates: equal-count substitutions need explicit adversarial coverage, not assumed protection.
4. Positive fixtures are genuinely native current/list.stdout + current/pour.stdout and historical equivalents. Include both show shapes and both before/after resolution states. Negative matrix: arbitrary Begin title; copied topology without bound mapping; foreign-root or swapped mapping; duplicate mapping IDs; wrong await_type; missing/extra blocks edge; parent-child masquerading as blocks; dangling gate; duplicate competing pair; count-preserving gate substitution; gate wrapper already closed while real human gate open; truncation, command error or unparseable JSON. Derived fixture mutations must be labeled synthetic, never native evidence.
5. Keep evidence raw bytes. evidence/ is the portable minimal bundle; source excerpts are line-numbered and commit-pinned. Full downloaded sources, binaries and disposable stores remain at /tmp/yf-exp001.dpIeDn for parent collection; no cleanup performed.
