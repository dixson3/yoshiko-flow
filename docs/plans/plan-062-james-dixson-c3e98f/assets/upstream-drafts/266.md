**Depended upon by plan-062, and deliberately not closed.** Recording what the gap cost, since
this plan is a direct instance of it.

The `## Gates` grammar recognises only `Type | Approvers | Condition | Test | Blocks |
Instructions`. plan-062 declared three capability gates carrying `test_class: probe` and
`cwd: repo-root`, and **`plan_extract.py` dropped both lines while `unparsed` stayed `[]`** —
so `--strict` did not flag the loss. A silent drop is the problem, not the missing fields: the
extractor reported a clean read of a document it had only partly understood.

The consequence is not cosmetic. A gate with no `test_class` is classified `manual`, and the
§5.2c execute-start sweep **never runs the manual class**. All three of this plan's gates would
have gone unswept, including the one standing between the newly-wired seam and duplicate public
reconcile comments.

**The workaround, for whoever fixes this.** plan-062's Issue 0.0 *sets* the metadata directly
at pour with `bd update --metadata`, then **reads it back and halts if a write did not take** —
a setter, not a detector. That distinction was deliberate (#273: prose naming an obligation is
skipped where prose naming a command is followed). The read-back is recorded at
`docs/plans/plan-062-james-dixson-c3e98f/records/sc14-gate-metadata.md`.

That workaround is sound but does not scale: it requires every plan to hand-write bead metadata
that its own `plan.md` already states, and it only works because a human wrote an issue whose
entire job was to remember. The grammar is still the right fix.

One measurement worth carrying into that fix: a repo-wide clause asserting "gates carry
`test_class`" is **permanently true** and therefore useless as a gate — 59 `test_class` lines
across 194 historical gate beads mean it passes before anything is poured. plan-062 tried that
route at pass 4 and reverted it at pass 5. The assertion has to be scoped to the plan's own
gates, or it certifies nothing.
