**Design input for plan-062, not a deliverable. Stays OPEN.**

plan-062 wired `land --apply` to its executor, which meant deciding how a test could drive
`--apply` past the tty gate. That decision is exactly this issue's territory, so the reasoning
is recorded here rather than left in a plan folder.

**Four mechanisms were measured** (`findings/exp-001` in the plan bundle). Two of them —
a `YF_LAND*`-style test environment flag, and wiring the currently-dormant `allow_list`
parameter — create a **production-reachable** bypass: anything that can set an environment
variable, or pass one argument, can open the consent gate. Given that this issue exists because
an executing agent closed that gate by asserting its own authorization, adding a second, easier
route would have been the wrong trade at any price.

**The chosen route adds none.** The defect sat *below* the tty gate, so a real pty was never
required to observe it. An in-process test monkeypatches the gate inside the test process only;
nothing about the shipped CLI changes. Three properties keep that honest:

- `test_tty_refusal_exits_three_not_one_or_two` is retained **byte-for-byte unmodified** as the
  real-process, gate-closed half — verified by extracting the function at both revisions and
  comparing, not by reading the diff.
- A source-level `ast` assertion proves `land_cmd` still *calls* `_land_tty_gate`, and calls it
  *before* `_land_execute`. That is the one gap a gate-stubbed test structurally cannot see: a
  gate that is deleted rather than stubbed.
- A criterion asserts no `YF_LAND`-prefixed escape appears in `plan_manager.py` at all.

**One finding here is actionable and is now filed separately as #334:** `allow_list=[None]`
opens the gate unconditionally in a no-tty environment (`None in [None]`), and the existing
test that should catch it passes vacuously because its own `or` fallback guarantees a
non-match. That is latent rather than CLI-reachable today, but it is one caller away.

The residue this issue names is unchanged: the tty gate remains **detection, not prevention**,
and `herdr pane run` remains a named known bypass. plan-062 did not run `land --apply` — the
handoff is an artifact for the operator, who performs the landing.
