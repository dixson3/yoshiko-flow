## 4. A DEFECT THIS FALSIFICATION FOUND (in the gate script, not the mutant)
   The first run drove the gate to a RED exit under the mutant. Cause: gate-doclint.sh
   treated ANY non-zero exit from change_validation.py as `harness_fail` — but that command
   exits non-zero exactly when the tier fails, i.e. precisely when the doclint row is doing
   its job. A failing tier was being reported as "the harness could not run", emitting no
   `commands` key at all.

   Same misclassification class as the `_common.sh` defect Issue 1.4 caught, and the fourth
   instance of "a control that cannot distinguish its signal" in this plan. Fixed: accept
   exit 0 and 1 from change_validation, harness_fail only on other codes, with the
   `has("commands")` parse check as the backstop either way.
