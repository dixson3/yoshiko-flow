**Fixed by plan-063 (Epic 4, `REQ-LAND-036`). Closing — and the issue title states the direction
backwards, so that is corrected here first.**

**The title says the field can never report dirty. Measured, it is the opposite.** The shipped
expression was `bool(_worktree_dirty(wt))`, and `_worktree_dirty` returns a **tuple**
`(dirty, files)`. `bool((False, []))` is `True` — a non-empty tuple is always truthy — so the
field was constantly `True` and could never report **clean**.

**And the type bug was not the deep problem.** `worktree_dirty` observed `.worktrees/<plan-id>`
while L16's post-condition — the thing a dry-run fact is supposed to predict — reads `ctx.root`,
the **primary checkout**. The field named the tree L16 does not check. So this needed a rename and
a redesign, not a one-character fix.

**The replacement — four fields:**

| Field | Type | Note |
| :-- | :-- | :-- |
| `execute_worktree_present` | bool | |
| `execute_worktree_dirty` | bool \| **null** | three-valued: `null` when there is no worktree, because `false` would assert "clean" about a tree that does not exist |
| `primary_checkout_dirty_outside_plan_dir` | bool | the fact that predicts L16 |
| `primary_checkout_staged_outside_plan_dir` | bool | |

The two `primary_checkout_*` fields are computed **via the same `_dirty_outside_plan_dir` helper
L16 enforces with** (#343), not by an inline predicate — one rule, one implementation.

**The facts stay boolean and the path lists live in `halts`.** That keeps the manifest digest
stable when the tree is clean, and makes dirt appearing between dry-run and apply a digest
**mismatch** for free.

**The digest exclusion, which needed its own requirement.** `execute_worktree_present` is
**landing-mutated**: L18's own teardown flips it `true` → `false`, and `REQ-LAND-011` re-derives
the manifest on resume — so a halt after a *partial* L18 would mismatch on a fact the landing
itself changed and route the operator back to `--dry-run` for a mutation performed on purpose.
`REQ-LAND-036` therefore excludes both `execute_worktree_*` fields from the digest's coverage set,
and `REQ-LAND-002` and `REQ-LAND-011`'s "every fact" wording is **amended** to match rather than
left in contradiction with it.

The verifying test asserts **both directions**: flipping an excluded fact leaves the digest equal,
**and** flipping `primary_checkout_dirty_outside_plan_dir` changes it. A one-direction assertion
is satisfied by a digest that covers nothing at all.
