**Fixed by plan-063 (Epic 3, `REQ-LAND-032`). Closing.**

This was the most severe defect the plan found, and it was found by the plan's own investigation
rather than filed by anyone.

L16 stages the plan folder (`git add -- <plan_dir>`) and then committed **the whole index**. A
file staged before the landing — by the operator, by a tool, by anything — was committed under
the plan's message and **pushed to `origin`**. L16 then reported `pass`, because its own
post-condition inspects `git status` **after** the commit, and the commit had removed the very
evidence the post-condition was looking for.

**The fix.** The commit is path-scoped to what the step staged:
`git commit -m <msg> -o -- <plan_dir>`. The staged-changes guard is scoped identically
(`git diff --cached --quiet -- <plan_dir>`), because an unrelated staged file otherwise makes the
whole-index guard say "there is something staged" while the scoped commit exits 1
`no changes added to commit` — a misleading failure at a post-outward-write step.

**Argument order is normative and was measured wrong once.** After `--` every token is a
pathspec, so the `-o -- <dir> -m <msg>` form fails with
`error: pathspec '-m' did not match any file(s)`, exit 1 — on **every** landing.

**Scoping the guard removes a misleading error; it does NOT remove the halt.** The post-condition
still sees the unrelated file and returns a halting fail. That halt is *intended*, and the tests
pin the expected envelope (`verdict: fail`, `halting: true`, the file absent from `HEAD`) rather
than merely the file's absence — writing them to expect `pass` would have invited scoping the
post-condition too, which re-opens this issue on the exact axis the gate guards.

**`REQ-LAND-020` was amended** to state the general rule this instantiates: *a post-condition
shall be able to see what the step did*. A step whose own write removes the evidence its
post-condition inspects is not fail-closed, however the assertion is worded.

**Tests.** Four new Tier-1 cases run against a **real sandbox git repo with a real bare origin**,
not `FakeRunner`. That matters: the only pre-existing L16 test drove a fake scripted with
`{"diff|--cached": _R(1)}`, so no real git ran and an argv real git rejects would still have
passed. The new cases cover the negative (a pre-staged unrelated file is not in the commit), the
positive (plan-folder writes including a newly created untracked file and a spaced path *are*
committed and pushed, and the landing still passes), and a repo without the `/.yf/` gitignore
anchor.

The dry run now **predicts** this halt before the irreversible boundary — see #333/#341.
