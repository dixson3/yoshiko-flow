**Fixed by plan-063 (Epic 4, `REQ-LAND-034` + `REQ-LAND-035`). Closing.**

A decision file written inside the work tree is seen by L16's post-condition and halts the
landing — **past the irreversible boundary**, with the reconcile comments already posted, the bead
tree closed and `status: complete` written. Two changes, because a suggestion is not a control.

**1. The prediction (`REQ-LAND-034`).** `land --dry-run` now reports a primary checkout dirty
**outside the plan folder** as a **halting** finding, computed via the same
`_dirty_outside_plan_dir` helper L16 enforces with. Dirt *inside* the plan folder is not a
finding — that is exactly what `git add -- <plan_dir>` stages.

**A halt strictly dominates a field.** The natural objection is that this blocks a landing over an
unrelated file. It is not an objection: **L16 blocks that landing regardless.** The only choice is
*where*. A dry-run halt costs one `git stash`. The L16 failure costs a landing wedged at
`L_CLOSED` whose recovery contract is explicitly *"retry-after-rebase, never revert"* — because
reverting would contradict outward statements already made.

**2. The control (`REQ-LAND-035`).** `land` now **refuses** a decision path inside the work tree,
and applies the same containment check to **every `body_path` the decision names** — `lander.md`
emits those as bare `"<path>"` with no guidance on where they live, and L7 reads them, so a body
file in the tree fails L16 for exactly the same reason.

The refusal is placed **beside `_land_assert_primary_checkout` and before the tty gate**, so a
refusal is never preceded by a write; the `body_path` half re-runs once the decision is parsed,
still before anything is written. Paths are resolved on both sides before comparison, so a symlink
or a `..` traversal cannot smuggle an in-tree path past a string test.

**3. The default.** `--dry-run`'s emitted `apply_command` no longer carries the literal
`<decision.json>` — a repo-relative-*looking* placeholder that invited the failure. It now defaults
to `${TMPDIR:-/tmp}/<plan-id>-decision.json`, which makes the safe path the path of least
resistance while the refusal above is what makes it a control.

**Also fixed in passing.** `resolvable_by_agent` was written in five places and **read in none**,
so this issue's new halt would have set a field nothing consumes. It now has a consumer: the dry
run partitions halts into agent-resolvable and operator-only, surfaces the agent-resolvable one
first in `remediation` (a `git stash` of unrelated local work is precisely the class a session can
clear without an outward-facing write), and emits both partitions in the output so the read is
observable rather than internal.
