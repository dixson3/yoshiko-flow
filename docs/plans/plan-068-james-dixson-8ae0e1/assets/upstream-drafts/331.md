**`land` now works under `execute.worktree: false`.** `_worktree_ensure`'s `opted-out`
short-circuit no longer returns above the base resolver; it routes to
`_worktree_ensure_in_place`, which **cuts and checks out** `<plan-id>-execute` in the primary
checkout from the strategy-resolved pinned base. The verdict shape is deliberately unchanged —
`viable: false, reason: "opted-out"`, so the caller still runs in-place — and measured,
`land --dry-run` goes from halting `execute-branch-missing` to `verdict: pass`, `halts: []`,
exit 0.

**Four defects, not one.** The branch-existence halt was the symptom; fixing it exposed three
more, each of which would have produced a green landing that meant nothing:

1. **Create-without-checkout would have been silently wrong.** The point is that `ctx.root`'s
   HEAD *is* the execute branch. Without the checkout, `_land_l1_down_merge` merged the target
   into whatever HEAD happened to be and reported `Already up to date.`, **exit 0**, verdict
   `pass`, journalling `L_DOWNMERGED` — a self-merge indistinguishable from a real down-merge in
   the manifest, the journal *and* the verdict. L1 now checks the branch out explicitly, and a
   failed checkout **halts**.
2. **The create had to be three-way.** `_worktree_ensure` runs on *every* `execute` invocation
   and its docstring promises "idempotent create-or-reattach", while `git checkout -b` on an
   existing branch exits **128** — so a two-way branch would have broken the second session of
   every in-place plan.
3. **The dirty-tree case had no guard.** Measured: `git checkout -b` on a dirty divergent tree
   emits `error: Your local changes would be overwritten by checkout`, exits 1, HEAD unmoved. It
   is now a declared refusal class reported *before* any checkout, and scoped to the two
   branch-moving arms — refusing while already on the branch would make every resumed in-place
   session unable to continue.
4. **The merge preview was symmetric.** `git diff <target> <execute_branch>` cannot distinguish
   "ahead" from "behind"; a branch strictly *behind* its target reported
   `changed_paths: ["work.txt"]`. Since `touches_skills` derives from that list and is **L19's
   redeploy precondition**, the defect propagated to whether the machine's installed toolchain
   gets rewritten. Worth recording: the obvious fix does **not** work — for `git diff`, `A..B` is
   not a range but sugar for the same symmetric endpoint diff, and it measured identical. The
   landed fix uses an explicit `git merge-base` left endpoint.
