**`REQ-LAND-037`** (new, `skills/yf-plan/spec/landing.md`): every process a landing step launches
**directly** goes through `LandingContext.run`; every *indirect* launcher **reachable from an
L-step** is a **declared** ctx-less helper resolving its cwd from an explicit argument.

**Eight sites routed**, not the seven "L8–L15" implies: L5's `recheck-criteria`; the
`LAND_CLOSE_CHAIN` loop (one site, seven launches); L12's cascade; L13's `complete-gate`; L14's
`bd list`; L14's `pour_fidelity.py`; L15's `update-status`; and L17's `bd show` read-back.

**The declared set is DERIVED, and the seed is process-launch primitives — never a helper name.**
`derive_land_launchers.py` seeds on `subprocess.*` / `os.system` / `os.popen` / `os.spawn*` /
`pty.*`, marks every containing function a direct launcher, takes the **transitive** closure over
the intra-module call graph, then BFS's from every `_land_l<N>_*` function. A hand-picked seed of
`{subprocess, _run_git, _run_shell, _run_change_validation}` misses `_repo_root` and `_git_root` —
which is how this issue's four cwd-less calls read as one. The seam edge is excluded **by name**,
so a future `def run` cannot silently explode the closure.

**`runner=` alone closes only half the escape.** `_validate_merged` and `_worktree_teardown` take
**both** `runner=` and `root=`, because **no runner intercepts a filesystem read**:
`_validate_merged`'s tier-1 decision is three filesystem/config probes keyed on `_repo_root()`.
Unrouted and unrooted, a pytest run would have made L3 execute this repository's FULL
`CHANGE-VALIDATION.md` tier and L18 run `git worktree remove` / `git branch -d` /
`git worktree prune` **in the real checkout**.

**`REQ-LAND-031`'s apparent carve-out was an over-read and is retired** (its own text unchanged):
it constrains the *call*, not how the callee launches.

**Enforcement** — `scripts/checks/check_land_seam.py`, an AST check with **two** clauses, because
a token-keyed check on `subprocess.*` is structurally **blind** to `_run_git`: clause 1 would pass
while clause 2 was violated at five call sites. Four negative controls, including the load-bearing
one — dropping a name from the declared allowlist with the code untouched fails clause 2 **while
clause 1 stays silent**, which is what establishes the clauses are independent.

**The rehearsal is now stub-free.** It previously disabled **six** steps via five monkeypatches
plus one decision-level skip — including `_validate_merged` (L3's *entire* validation) and
`_worktree_teardown` (L18). It now has **zero** monkeypatches: the real step functions run against
one injected runner that passes `git` **through** to a sandbox with a local bare `origin` and
intercepts everything else with argv-recognising fakes that **fail at 127** on an unrecognised
argv rather than returning 0. `stubbed_steps` is derived from **both** sources — monkeypatches
*and* decision-level adjudications — and from `LAND_EXECUTOR`, so the L-span of each executor
function is computed rather than hand-written; the old record named three labels while hiding five
L-numbers. And the rehearsal now **executes under pytest** instead of being read from a committed
artifact that could rot silently.
