## How "equal-or-newer" is measured

Per the review carry-forward (issue 5.2), this is deliberately **not** a subjective
judgement. It is two mechanical checks:

- **(A) Set membership** — every `yf-*` artifact under `~/.claude/skills/` has a repo
  counterpart at the same relative path under `skills/`.
- **(B) Content check** on the two artifacts where existence alone proves nothing: the
  `yf-herdr/` import and the locally patched `plan_manager.py`.

## Scope, stated explicitly

Three exclusions, each a deliberate decision rather than a filtered-away inconvenience:

| Excluded | Why |
|:--|:--|
| `herdr`, `mermaid`, `naba` (15 files) | **Third-party skills** installed alongside. This repo does not ship them, so it cannot be their superset. Reported by the script, never silently dropped. |
| `__pycache__/`, `*.pyc`, `.DS_Store` | Build/OS noise, per the plan. |
| The install stamp `<!-- yf-skills: v=… tree=… -->` | The installer injects it into every `SKILL.md`. Comparing without filtering it reports **19 false positives** — the first trap `exp-01` found. |

`plan_manager.py.pre-incubator-root.bak` is checked separately: it lives in the plan
folder (Epic 1's rescue), not under `skills/`, because it is a snapshot of a user-scope
file rather than a repo skill artifact.

## Reading the two non-obvious lines

**`yf-herdr/*` reports DIVERGED, and that is correct.** The repo copies were
*deliberately* edited during Epic 3's import: `SKILL.md` dropped `depends-on-skill:
[herdr]` and gained the prose soft-dep section, `SPEC.md` went DRAFT → Active with an
amendment log and `REQ-HERDR-040/041`, and `README.md` gained Install / Usage /
Behavior model / Layout sections. Byte-equality here would mean the import had **not**
been brought to repo discipline. The pre-import snapshot is preserved verbatim at
`references/user-scope/yf-herdr/`, so nothing was lost.

**`plan_manager.py` is checked by behavior, not bytes.** The local patch was
re-implemented on the canonical `.yf/` idiom rather than ported verbatim (that was the
whole point of ordering #100 before #107), so the files legitimately differ. What must
survive is the patch's behavior, and all four properties are present: configurable
`plans-root` and `incubator-root`, a dependency-free import-time reader, and the
original defaults.

## Conclusion

The repo now contains everything that lived only in the operator's user-scope install.
The three repo-only files (`SPEC-TEMPLATE.md`, `test_config_tiers.py`,
`test_review_verdict.py`) are the intended end state — the repo is a **superset**, not a
mirror. A redeploy would overwrite user scope losing nothing.
